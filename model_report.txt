======================================================================
STEP 3: Feature Engineering / Selection
======================================================================
Using 28 input features (demographics + signs/symptoms only):
   Age, Gender, Address, Education, Occupation, Income, Paleness, Fatigue, BrittleNails, Dizziness, SOB, PoorSleep, Irritability, HairLoss, DrySkin, Appetite, ColdIntolerance, Headache, Tongue, EarNoise, Tachycardia, Infections, Bruising, RLS, Dysphagia, Pica, BlueSclera, AngularStomatitis
Lab test columns (24 CBC/Peripheral-Smear parameters) are EXCLUDED from inputs, per the study's aim of diagnosis without requiring a blood test. Outcome (case/control) was generated using the exact same classify_lab_verdict() core-panel rule the apps use to confirm IDA from a real patient's lab report, so training stays in sync with the app's lab-confirmation logic.

======================================================================
STEP 4: Splitting into Train / Validation / Test sets
======================================================================
Training set  : 14000 records (70%) - used to train each model
Validation set: 3000 records (15%) - used to compare/tune models
Test set      : 3000 records (15%) - held back, used ONLY for the final report
Numeric features were standardized (mean=0, std=1) for the SVM and Neural Network candidates, which are sensitive to feature scale. Tree-based models (Decision Tree, Random Forest) use the raw values, since they don't require scaling.
